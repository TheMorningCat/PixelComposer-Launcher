## 8.1 页签构成（六页签）

| 页签 | 内容 | 数据来源 | 默认排序 | 空态文案 |
| --- | --- | --- | --- | --- |
| **近期文件** | PXC 自己的最近列表，保持数组原顺序 | PXC `recent.json`（只读） | 不排序（PXC 就是最新在前） | `PXC 还没有近期记录。用它打开过一次工程后就会出现在这里。` |
| **全部** | **工程库 ∪ 启动历史**，按路径去重 | 启动器 `projects.json` | 最近一次活动 ↓ | `还没有内容。用启动器打开一个工程，或把工程加入工程库。` |
| **工程库** | 用户显式加入的工程：导入的文件、导入的文件夹、从「近期文件」右键加入的文件或其所在文件夹 | `projects.json.imported` | 加入时间 ↓ | `点右上「导入 PXC 文件 / 导入工程文件夹」，或在「近期文件」里右键加入。` |
| **启动历史** | 用启动器成功启动过的工程（**不显示启动次数**，次数仅内部记账） | `projects.json.history` | 最近启动 ↓ | `还没通过启动器打开过工程。` |
| **收藏** | 收藏过的工程（任意来源） | `projects.json.favorites` | 收藏时间 ↓ | `点行左侧的星标就能收藏。` |
| **自动恢复** | `Autosave/` 下全部 `.pxc`，不折叠不去重（口径见 `docs/03` §7.5.2） | PXC `Autosave/`（只读） | 文件 mtime ↓ | `没有自动保存文件。` |

页签顺序固定为：**近期文件 · 全部 · 工程库 · 启动历史 · 收藏 · 自动恢复**。

> 六个页签文字宽合计约 **458 px**（含 8 px 间距），右上搜索框 300 px，加上左右 `pad = 28`
> 需要内容宽 ≥ **810 px**。窗口再窄时页签带优先保持、搜索框收到 220 px。

### 8.1.1 为什么「导入」改名「工程库」

原来那一页装的是"用户显式纳管进来的东西"——导入的文件、导入的文件夹，现在还要装"从近期文件右键加入的"。
"导入"描述的是**动作**，只覆盖了第一类；"工程库"描述的是**这一页是什么**，三类都能装进来。

### 8.1.2 为什么「全部」是并集

用户对"全部"的期待是"我这儿所有工程"。如果它只等于 `history`，那么用别的程序打开过的、或者手工拖进来的工程就不在里面——
那它其实叫"启动历史"，不该占着"全部"这个名字。并集之后，各页签的关系是：

```
近期文件（PXC 的）      全部（启动器的）
                          ├── 工程库（用户显式加入）
                          └── 启动历史（用启动器打开过）
自动恢复（PXC 的）      收藏（跨来源的标记，不属于上面任何一支）
```

并集的两条实现口径（已拍板）：**按路径去重**（同一工程既在库又在历史里，只出现一次）；
**卡片不标来源**（行高 72 已排满，来源是次要信息，需要时在右键菜单里提示即可）。

### 8.1.3 存储字段不改名

界面叫"工程库"，`projects.json` 里的字段**仍然是 `imported`**。
改名要写迁移代码、且旧版本启动器读新文件会当成空库——为了一个显示名不值。语义映射写在代码注释里。

## 8.2 导航：双击进入文件夹

| 动作 | 结果 |
| --- | --- |
| **双击文件夹行** | 进入：列表内容切换为该文件夹的**直接子项**（子文件夹 + 该层的 `.pxc`） |
| 单击文件夹行 | 只选中，不进入 |
| 双击 `.pxc` 文件行 | 启动（与「启动」按钮同一条 `startProject()`） |
| 面包屑「← 返回」 | 回到上一层；已在根层时隐藏 |
| 在根层按「返回」 | 无动作（不退出页签，避免误触把用户弹回别处） |

**面包屑**（进入态才出现，替换掉当前页签名那一行左侧的标题区，或紧贴在页签带下方）：

```
← 返回    工程库 / D:\Canvas / 吸收
```

- 每一段可点，点第 N 段回到第 N 层。
- 第一段是**页签名**（工程库 / 全部 / 近期文件…），点它回根层。
- 路径段超过 3 个时，中间用 `…` 折叠，只留首段与末两段。

### 8.2.1 只列直接子项，不递归

进入一个文件夹只列它**这一层**的东西：子文件夹行（可继续双击进入）+ 该层的 `.pxc`。
理由：`Autosave` 那样的目录一次递归能炸出 3000 条，"进入"就失去了"我在看某个具体位置"的意义。
需要一次看全时用搜索（见 §8.2.2），不走递归展开。

### 8.2.2 搜索与筛选的作用域

| 状态 | 搜索 | 筛选 | 排序 |
| --- | --- | --- | --- |
| 根层 | 当前页签全部条目 | 当前页签全部条目 | 当前页签 |
| 进入态（无搜索词） | 当前文件夹这一层 | 当前文件夹这一层 | 当前层 |
| 进入态 + 有搜索词 | **自动退出进入态**，在整页签范围搜 | 整页签 | 整页签 |

搜索框一旦有内容就退出进入态 —— 用户打字是为了"找东西"，不是为了"在这一层找"。范围悄悄缩成一层，
最常见的后果是"我明明有这个东西，怎么搜不到"。

### 8.2.3 进入态不落盘

重启回到根层。进入态是**浏览位置**，不是配置；记住它反而会让下次打开时"东西怎么都不见了"。

### 8.3.1 版本徽章（固定宽 + 圆点）

```
┌──────────────────────────┐
│ ●  1.20.1.0              │   ● = 6×6 圆点，x = 10，垂直居中
└──────────────────────────┘   文本 x = 22，宽 62，11px，左对齐
   宽 92，高 22
```

| 圆点色 | 含义 | 徽章底 / 字 |
| --- | --- | --- |
| 绿 `#5FE0A0` | 本机已登记这个版本，双击能直接开 | `#1E5B45` / `#5FE0A0` |
| 橙 `#F0C060` | 版本已知，本机没有（双击会弹跨版本协商） | `#6B4E14` / `#F0C060` |
| 红 `#FF7F7F` | **识别不出**（读到了，但结构不属于任何已知族） | `#612525` / `#FF7F7F` |
| 灰 `#9AA3B0` | **识别中**（还没轮到它，是过程不是结论） | `#3A3F48` / `#9AA3B0` |

- **红 vs 灰必须分开**：混成一档会让用户以为"再等等就好了"，而「识别不出」永远好不了。
  红是结论，灰是过程。
- **底宽固定 92**：版本串长度在 `1.18` 到 `1.20.1.0` 之间变化，按内容撑宽会让整列左右跳。
- 文本超过 62 px 时按字符收尾成 `…`（`1.20.1.0` 只有 8 字符，正常不会触发）。
- 未识别（`detected == false`）时圆点灰、文本 `…`，不写"未知"—— 写"未知"会和"识别失败"混淆。

**版本号改回默认字体**（与卡片其它文本一致）。历史上为避免 NotoSansSC 的「1」底部衬线吃掉紧随的
小数点（`1.20.1.0` 渲染成 `120.10`），曾用过等宽 `JetBrainsMono-Medium.ttf`；本版按需求改回默认字体以统一观感。
**代价**：上述「1 吞小数点」风险回归，`1.20.1.0` 可能被读成 `120.10`。若日后此问题在实际显示中复现，
可在 `composeWbRow` 的 `.pillt` 重新挂 `wbVerFontOf(pill)`（函数与字体仍在，`kVerMonoFile` 未删）。

### 8.3.2 副行只到文件夹

| 行 | 副行显示 |
| --- | --- |
| 文件 `D:\Canvas\吸收\吸收.pxc` | `D:\Canvas\吸收` |
| 文件 `D:\吸收.pxc`（就在盘根） | `D:\` |

### 8.3.3 表头：筛选 / 排序 / 刷新同一条底板

这一行装进一条**工具条底板**（`kBarY = kSortY − 5 = 105`，高 34，圆角 8，底色介于页面底与卡片底之间）。
底板存在的理由：筛选、排序、刷新是**一条工具条**，散着画看不出归属，也挡不住"这三件事是一伙的"这个结构。

内部控件一律 **24 高、中线 y = 122**；列表从 y = 150 起。

| 控件 | 位置 | 行为 |
| --- | --- | --- |
| `文件名` | x = 84，宽 130 | 名称 ↑ / ↓ |
| `修改时间` | `listRight − 208` 左半，宽 92 | 时间 ↑ / ↓（与版本**各自独立**） |
| `版本` | `listRight − 208` 右半，宽 92 | 版本 ↑ / ↓ |
| 筛选（漏斗，28×24） | 右端**倒数第二枚** | 点开 / 收起筛选浮窗；激活时底衬 accent |
| 刷新（撤销箭头，28×24） | 行**最右** | 重新扫描列表 |
| `重置`（44×24） | 筛选左侧，**仅筛选激活时出现** | 清空筛选与日期区间 |

- **两枚图标按钮并排放在最右**（间隔 6），不再一左一右分居两端。
- **图标用 EUI 自带的 Font Awesome 7 Free 图标字体**：`ui.text().icon(码位)`，
  `FILTER = U+F0B0`、`UNDO = U+F0E2`（已用字体 cmap 核对字形存在）。换掉内联 SVG 的两个独立理由：
  ① 不必再拼 SVG 字符串 —— `R"(...)"` 里 `)"` 是闭合符，写 `fill="` 必须写 `fill=")"`，否则吃掉开引号、
  生成残串，`nsvgParse` 静默失败、按钮空白（踩过一次）；② 图标跟字号走，和同排文字天然同高，不用手算尺寸。
- **排序文字与图标按钮同一中线**：都在 24 高行框里 `verticalAlign(Center)`。历史实现是 18 高、顶对齐，
  比按钮高 3px（本轮截图实测中心差 3px，已修）。
- 卡片内「修改时间 / 版本」仍竖排同一列（列左 `cardW − 208`），排版不动。

### 8.3.4 文件夹行

- 右端「进入」按钮（C1）：带边框圆角底 + `>` 图标，垂直居中，仿工程卡的「启动」按钮。`mouseArea` 不支持 `border`，故底衬用 `ui.rect` 画、`mouseArea` 叠在上层做透明命中区。
- **文件夹卡的标题 / 路径位置与工程卡完全一致**（`kNameY = 14`、`kSubY = 42`）。曾经为了让标题与左侧
  文件夹图标垂直居中，把文件夹行单独放在 `cy+25 / cy+47` —— 结果是两种卡片看起来不像同一种东西，已回退。

**进入文件夹后那一行面包屑**（`← 全部 / <文件夹名>`）才是"当前在哪一层"的提示：字号 13.5、行高 `kCrumbH = 24`，
与左侧返回按钮同中线。它占掉表头那行，排序底板与列表整体下移 `kCrumbShift = 30`。

### 8.3.5 卡片内两处像素级修正（截图实测）

| 项 | 现象 | 做法 |
| --- | --- | --- |
| 收藏星 | 观感上比标题偏下 | Font Awesome 星形在 18px 行框里天然偏下：实测标题 ink 中心 287.5、星 ink 中心 290.0，**差 2.5px**。`starY = nameTop + (22−18)/2 + kStarNudgeY`，`kStarNudgeY = −2.5`；改字号 / 行高要重量 |
| 副行（路径） | 可点区域与悬浮下划线比文字宽一截，点空白也会定位到文件夹 | 命中区与下划线宽度改用 **`core::TextPrimitive::measureTextSize()` 的真实字形宽度**（内部按内容缓存）；裁剪仍用 `wbFit`（v4 起它先用真实宽度判一次"放得下就别截"，再回退到 em 估算的截断循环 —— 纯 ASCII 的版本号 `1.20.1.0` 实测 56 px、em 估算 69 px，只按估算判会把它截成 `…20.1.0`）。`wbTextW` 是按 em 估的（ASCII 记 0.56em），纯 ASCII 路径会高估三四成 —— 这就是"下划线明显超出文字"的来源 |

## 8.4 图标：把素材 SVG 接进来

素材：`素材/素材-PXC icon.svg`（128×128，两块橙 `#FF9166` + 深灰 `#313143` / `#272736`）。

**可行性已确认**：EUI-NEO 自带的 `core/render/image_source.cpp` 里已经 `#define NANOSVG_IMPLEMENTATION`
+ `NANOSVGRAST_IMPLEMENTATION`，`.svg` 走的是原生光栅化路径，不需要我们自己接第三方库。

| 项 | 决定 |
| --- | --- |
| 存放 | `launcher/data/icons/pxc.svg`，构建后随 `data/` 同步到 `<exe目录>/data/icons/` |
| 加载 | `ui.image(id).source("<exe>/data/icons/pxc.svg").size(40,40)` |
| 清晰度 | 按 **2 倍**目标尺寸光栅化（内部 80×80），避免 40px 显示时边缘发毛 |
| 缓存 | 每帧都建 image 元素，但**路径串相同**，由框架按源串缓存，不重复解析 |
| 找不到文件 | 退回现有自绘（橙红色块 + 字体图标 `0xF15B`），不显示破图 |

文件夹图标继续用图标字体（`0xF07B` 关 / `0xF07C` 开），SVG 只用于 `.pxc`。
理由：文件夹是"另一种东西"，用同一套矢量图的视觉重量会压过工程文件。

> 注意：SVG 光栅化发生在 `image_source` 的加载路径上，**不能在 `dslAppConfig()` 里同步读盘**
> （`docs/03` §7.5 的教训：每帧调 20+ 次）。这里只在 `composeWbRow` 里给元素设 source，
> 解析由框架自己的缓存层做，不进我们的帧循环。

## 8.5 筛选浮窗

### 8.5.1 入口

替换掉 v3 的四档漏斗 chip，改成：

```
只看   [ 筛选 · 2 ]  [ 重置 ]                                    [ 刷新 ]
```

- `筛选` 按钮：未生效时显示 `筛选`，生效时显示 `筛选 · N`（N = 生效的条件组数），底衬换成 accent 淡色。
- `重置`：一键清空所有条件，仅在有条目时出现。

## 8.6 文件夹内的版本识别（现状 bug）

**症状**：进入/展开文件夹后，里面 `.pxc` 的版本列一直是 `…`，永远不填。

**根因**：懒识别 `wbTickDetect()` 只遍历 `g_wb.all`，而文件夹里的子项存在
`g_wb.children[folderPath]` 里，从来没进过识别队列。

**修法**：`g_wb.all` 作为**唯一识别队列**——进入文件夹时把该层的 `.pxc` 直接放进 `g_wb.all`
（列表的 `rows` 指向 `all` 的下标），子项不再单独存在 `children` 里。这样：

| 原来 | 现在 |
| --- | --- |
| 根层在 `all`，子项在 `children[path]` 两张表 | 每层一份，统一放 `layers[dir]`；`all` 只指向当前层 |
| 识别只覆盖 `all` | 识别遍历 `all`（**当前整层**，不是过筛后的 `rows`），天然覆盖所有已加载条目 |

顺带解决：识别结果按 `path+size+mtime` 落 `detect_cache.json`，切层/重进时由 `wbApplyCached()`
直接回填，不会丢。收藏按路径查 `Store`，与层无关。

## 8.8 本轮同时修掉的两个 bug

### 8.8.1 版本号尾部 `.0` 被省略 → 明明有对应版本却弹协商窗

PXC 写进 `.pxc` 的版本号会**省掉尾部的 `.0`**：装了 `1.20.1.0` 的客户端把工程存成 `"1.20.1"`，
`1.18.5.0` 存成 `"1.18.5"`。版本库里登记的却是 exe 的完整四段版本，于是：

```
findMatching("1.20.1")  vs  登记项 "1.20.1.0"  →  字符串全等比较 → 不命中
→ StartResult::NoVersion → 弹"这个工程需要的版本，本机没有"
```

修法（`pxc_reg` 增加两个函数，四处共用同一口径）：

| 函数 | 行为 |
| --- | --- |
| `normalizeVersion("1.18.5")` | → `"1.18.5.0"`；两段 `"1.20"` → `"1.20.0.0"`；带后缀 `"1.21rc2"` **原样返回**（猜不出语义就不猜） |
| `sameVersion(a, b)` | 数字四段相等即同一版本；任一侧带后缀（非纯数字点分）退回字符串全等 |

接入点：`applyDetect()`（识别结果入库即补齐）、`findMatching()`（匹配）、`passFunnel()`（筛选）、
`wbVersionRegistered()`（卡片圆点）、以及读 `detect_cache.json` 时补一次（老缓存里存的是三段值）。

顺带修：`shouldBackup` 的 `forced` 判定原来用 `!=` 比字符串，`1.20.1` vs `1.20.1.0` 会被当成
"强制跨版本"每次都白备份一份，改用 `sameVersion`。

回归：`pxc_project_test` 新增 §14 共 14 条断言，覆盖规范化 / 等价判断 / 带后缀不误判 /
`findMatching` 命中 / 启动入口不再走 `NoVersion` / `applyDetect` 入库补齐 / 漏斗同口径。

### 8.8.2 跨版本风险的说法改回用户口径

**用户口径：跨版本的风险是直接损坏文件 —— 一打开工程文件就报废。不是"无法用旧版本启动"。**

| 位置 | 旧文案（错） | 新文案 |
| --- | --- | --- |
| 协商弹窗风险行 | `跨版本保存不可逆：新版本写过之后，旧版本可能再也打不开这个文件。` | `跨版本的风险是直接损坏文件：用不匹配的版本打开并保存过一次，这个工程就报废了。` |
| 候选行理由 | `跨结构打开可能失败` | `跨结构打开会损坏文件` |
| 弹窗结论 | `但跨结构打开可能失败。` | `但跨结构打开会损坏文件。` |

差别是实质性的：「旧版本打不开」意味着"用新版本还能救回来"，是可逆的、只是不方便；
「直接损坏文件」意味着"这个工程没了"。前者会把用户往"要不我试试"上推，后者才会让人老实建副本。

### 8.10.1 两处实现坑（本轮踩到并修掉）

- **筛选必须能筛出「识别不出」**：状态 chip 的显示序（可启动/缺失/识别不出/识别中）与 `VerState`
  枚举序（Pending=0/Ok=1/Missing=2/Unreadable=3）不一致。旧代码用显示下标直接 `1<<k`，
  点「识别不出」取到的是 Missing 的位 → 筛出 0 条。现统一走 `stateChipBit(idx)=1<<stateChipAt(idx)`，
  显示序与位映射只在 `project_index` 一处定义，UI 与测试共用。
- **懒识别 + 筛选会互相锁死**：识别是按帧推进的（12ms/帧），若只遍历「当前可见行」`rows`，
  被筛掉的条目永远得不到识别，就永远停在「识别中」→「只看识别不出」永远空。现 `wbTickDetect`
  遍历整层 `all`，且识别出结果后若筛选生效就重算 `wbBuildRows()`。

### 8.11.2 贴底布局的坑：`screen.height` 是窗口外框，不是客户区

现象：说明挪到按钮下方后，整行被窗口底边裁掉一半（只剩上边缘几个像素）。

`composeWorkbench` 里列表高度是 `g_scrH - listY - 预留`，而 `g_scrH = screen.height`。
问题是 **`screen.height` 报的是窗口外框高度（含标题栏），客户区比它矮约 30 px**。
于是任何"算到 `g_scrH` 就以为到底了"的布局，都会被标题栏吃掉最后 30 px。

修法：底部预留从 `96` 改成 `134`，并把它的构成写进注释
（状态行 18 + 间距 4 + 按钮 26 + 间距 4 + 说明 16 + 底部留白 12 = 80，再补 30 抵掉标题栏）。

> **教训**：别按"屏幕高 - 顶边 - 常量"猜底部位置。只要内容贴底，就必须给标题栏留出那 30 px，
> 否则表现是"某些分辨率下刚好可见、某些下被裁"，很容易误判成偶发渲染问题。

#### 8.11.2.1 11-04 复测：这条 30 px 已经不成立了

工程页底部回收预留时顺带量了一次（窗口外框 1056×759、客户区 1040×720）：

| 量 | 值 |
| --- | --- |
| `screen.height`（`g_scrH`） | **720** |
| 客户区高 | 720 |
| 外框高 | 759（差 39 = 标题栏 + 上下边框） |

判据是反推的：按 `listH = g_scrH - listY - 38` 算出的列表下缘正好落在 682，状态行画在 690..708，
距客户区下缘 12 px —— 只有 `g_scrH = 720` 才能对上；若 `g_scrH = 759`，列表会一路顶到窗口底边。

所以**现在别从贴底预留里再扣 `clientInsetH()`**：多减 39 px 就是一条凭空多出来的空白。
当年那 30 px 是真的（`docs/04` §8.11.2 的现象、toast 掉出下缘都是实测过的），只能是后来取屏幕尺寸的
路径变了。**结论：这条属于"换 DPI / 换主题 / 换框架版本都要重量一次"的量，别当常量继承。**
量法照 `tmp/shot_projects.py`：抓客户区 → 从底部往上扫非背景像素 → 看最后一条内容距下缘多少。
