## 5. 运行期：生成引擎

### 5.1 英文骨架获取（**决定"该版本需要什么"**）

> **2026-11-03 第四次修订，以 `docs/08` §8.1 为准**：骨架 = **用户选定的「目标版本」自己那份英文**，
> 且**不再有内置骨架**（已整份删除）。三次被推翻的演进过程只留在 `docs/08` §8.1.2，这里只记现行结论。

优先链（**只取第一个，不合并**）：

| 序 | 路径 | 说明 | `origin` |
| --- | --- | --- | --- |
| 1 | 目标版本安装目录 `data/locale/en` | itch 明文，最权威（1.18.5 样本实测含 UI/config/nodes/words） | `install-en` |
| 2 | 同上 `data/locale/sample locale` | 该版本没发 `en` | `install-sample` |
| 3 | 同上 `pack/locale.zip` 里的 `en/` | **Steam 无 `data/` 明文**，做法见 `docs/08` §8.1.7 | `install-zip` |
| 4 | 同一 zip 里的 `sample locale/` | zip 只带 sample 时 | `install-zip-sample` |
| 5 | 用户目录 `Locale/en` + `Locale/version` | **只在降级时用**。这一对是同一次运行写下的，`version` 能说出版本（本机 `{"version":118050}` = 1.18.5，`en` 正好 530 节点） | `user-en` |
| 6 | 用户目录 `Locale/sample locale` | PXC 自己解出来的真骨架，但**没有版本标记**（`version` 只记最近一次运行）；本机 840 节点对不上任何已装版本 | `user-sample` |
| 7 | 用户目录 `Locale/nodes_missing.json` | 汉化面板「导出缺失节点」的**差集**，节点/端口定义完整；只在 5、6 都没有时用（分析见 `docs/08` §8.1.5.1） | `user-missing` |
| 8 | 兜底规则（§5.6，最小文件集） | 极端情况 | `fallback` |

1~4 是"目标版本自己的"（Steam 版靠 3/4，`docs/08` §8.1.7）；5~8 只在降级时走（判据与文案见 `docs/08` §8.1.5）。

三条硬规则：

| 规则 | 原因 |
| --- | --- |
| **不合并多源** | 原 `resolve()` 会把后续来源里"骨架没有的节点"补进来（`baseline_scanner.cpp:169-180`）——那等于运行期偷偷做"全键并集"，生成出来的包带了本版本没有的节点。**只取第一个候选**（实测：目标 1.18.5 时并集 530 → **867** 节点，详见 `docs/08` §8.1.8） |
| **不内置骨架** | 27 个退役节点（`Node_PB_*` 等）在对照表里 **0 条目**，内置换不来任何译文；而用户装着的版本永远比内置那份更合适。数据与删除清单见 `docs/08` §8.1.4 |
| **字体槽位表是唯一例外** | `en/` 不带 `fonts/`（明文与 zip 都不带）。`fonts/fonts.json` 是渲染槽位表、与版本结构无关，允许从**同一版本的 `sample locale/fonts/fonts.json`** 补这一个 json（不搬字体本体、不跨版本） |

为什么不能"一份包服务所有版本"（2026-11-03 实测）：端口译文在 PXC 侧**按数组下标**查
（`locale_data.gml:137` `lst[index]`），1.22 的包喂 1.18.5 会有 135 个节点 / 439 个端口显示**别人的中文**；
反过来用低版本骨架喂高版本会大面积回退英文（1.19 骨架跑 1.20.1：1799 个端口没译文）。
四个版本两两的取舍矩阵见 `docs/08` §8.1.2.1。

用户目录定位：读 `%LOCALAPPDATA%\PixelComposer\persistPreference.json` 的 `path`；读不到回退 `%LOCALAPPDATA%\PixelComposer`（再不行退 `%APPDATA%`）。**启动时自动定位，不再让用户点按钮或弹窗手选**；设置页里仍可手动覆盖（`docs/08` §8.7）。

**「安装目录」不再由用户手选**（2026-11-01 拍板）：汉化页那个「选择安装目录」按钮已移除，`gen.install_dir` 字段一起删。
1~4 的来源改成**自动推导**：

```
版本库里有登记的 exe  →  installDirOfExe(exe)  →  data/locale/en → data/locale/sample locale
                                            →  pack/locale.zip 的 en/ / sample locale/（Steam）
一个 exe 都没有        →  目标版本无从谈起，直接从 5（用户目录 sample）开始，再退 6、7
```

也就是普通用户永远走自动链，维护者要指定**别的一份**骨架则去构建器的两个入口（`docs/01` §4.1.1）：
「导入新版英文包骨架」给目录、「选择新版 PXC 路径」给 exe。两条路互不影响：构建器那只改"建表用的骨架"，
不参与运行期生成。

### 5.2 生成规则（每类文件一条）

| 文件               | 规则                                                                                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `words.json`     | 骨架 key 全保留；值 → 查 `words.<key>`，按「界面文本」表达式渲染；未命中保留英文值                                                                                                 |
| `nodes.json`     | 骨架节点逐个：`name`/`tooltip` 查 `nodes.<id>.*`；`inputs`/`outputs` 按**英文端口名**查；`display_data` 只对**字符串项**按英文值查。`-1.0` / `@ref sprite(...)` / **任何非字符串值原样复制** |
| `UI.json`        | 骨架有 `UI.json` → key = 骨架 key ∪ 对照表 `ui.*` 补充键；骨架没有（如 1.22 官方 en）→ **由对照表 `ui.*` 单独生成**，作为补充（PXC 支持该文件，1.18 时代官方就有）                                   |
| `junctions.json` | 结构照抄；`note` 改写为**实际写出的 md 文件名**（有中文版用中文名，否则保留英文名）                                                                                                    |
| `notes/*.md`     | 骨架语言目录带 `notes/` 才生成：有中文版写中文版（文件名用中文名），否则复制英文版。1.22 官方 en 不带 notes → 该项跳过                                                                            |
| `config.json`    | 骨架键保留 + **强制 `per_character_line_break = true`**（中文，官方要求）                                                                                            |
| `fonts/`         | 复制选定字体的 ttf/otf；`fonts.json` 槽位 `path` 指向复制过去的文件，槽位与 size 沿用骨架（骨架无 `fonts.json` 时套用 `sample locale` 的槽位表）                                            |


### 5.3 三条硬约束（防闪退 / 防缺字）

1. **结构照抄骨架**：骨架有的 key 一个不少（旧包缺 key 是闪退主因）。
2. **类型不动**：**基准字段是非字符串（`{}` / `[]` / `bool`）时原样复制，不翻译也不"修正"成字符串** —— 官方 en 自带这类值且 PXC 能正常读（1.22 原版实测 18 处），改类型才是风险。只有"基准是字符串"时才查表替换。
3. **不写空串**：无译文回退英文，绝不写 `""`。

### 5.4 显示表达式：**按内容分项配置**（决策 D2 已定）

每类内容一个独立表达式，占位符 `%en` / `%zh`，其余字符原样输出。默认全 `%zh`（纯中文）。

| 槽位    | 覆盖内容                            | 默认    |
| ----- | ------------------------------- | ----- |
| 节点名   | `nodes.<id>.name`               | `%zh` |
| 节点提示  | `nodes.<id>.tooltip`、端口 tooltip | `%zh` |
| 输入端口名 | `inputs[].name`                 | `%zh` |
| 输出端口名 | `outputs[].name`                | `%zh` |
| 下拉项   | `display_data` 里的字符串项           | `%zh` |
| 界面文本  | `words.json` + `UI.json`        | `%zh` |

**三个预设**（一键填入全部槽位，之后仍可单独改）：

| 预设   | 节点名       | 其余槽位  | 说明                               |
| ---- | --------- | ----- | -------------------------------- |
| 纯中文  | `%zh`     | `%zh` | 默认                               |
| 中文在前 | `%zh_%en` | `%zh` | 例：`混合_Blend`，与 1.18 `ce-zh` 实测一致 |
| 英文在前 | `%en_%zh` | `%zh` | 例：`Blend_混合`，与 1.18 `ec-zh` 实测一致 |

预设只在节点名上做双语、其余保持中文 —— 这是 1.18 双语包的实际做法（端口名和下拉项再拼一遍会把节点撑爆）。用户若想更彻底，可自行把其它槽位也改成双语表达式。

渲染规则：中文缺失则回退英文（等价于 `%zh` 退化成 `%en`），并清理残留空括号 `[] () （）`。

### 5.4.1 字体（决策 D3 已定）

两个下拉：**界面字体** / **代码字体**。

| 来源                | 字体                                                                                               | 体积        | 处理                    |
| ----------------- | ------------------------------------------------------------------------------------------------ | --------- | --------------------- |
| 内置（随程序分发，取自现有汉化包） | NotoSansSC-Medium / SemiBold / Bold                                                              | 各 ~2.4 MB | 打包（1.22 包在用，中文正文）     |
| 内置                | FiraCode-Medium                                                                                  | 183 KB    | 打包（1.22 包在用的等宽）       |
| 内置                | JetBrainsMono-Medium                                                                             | 267 KB    | 打包（1.18 包在用的等宽）       |
| 系统字体              | 枚举 `%WINDIR%\Fonts`（实测 532 个 ttf/otf/ttc）                                                        | —         | 用户选中后复制进目标 `fonts/`   |
| 不打包（体积过大）         | LXGWNeoXiHeiPlus 8.6MB、LXGWWenKaiMonoLite-Bold 10.8MB、YeZiGongChangZhaoPaiTi 4.4MB、SF-Pro 20.8MB | —         | 用户若要用，可指向自己本地的 ttf 文件 |

内置合计 ≈ 7.9 MB。槽位（`h1/h2/h3/h5/p0/p0b/p1/p1b/p2/p2b/code/sdf…`）沿用骨架 `fonts.json` 的 size，只替换 `path`。

### 5.4.2 输出目录名（**写进启动器配置**）

语言文件夹名由用户在启动器里设定，存 `launcher.json` 的 `lang_dir`（默认 `zh`，可填 `ce-zh` / `ec-zh` / 任意名）。  
因为 PXC 界面语言的持久化位置还没找到，**首次需要用户在 PXC 偏好设置里手动选一次这个文件夹名**；生成完成后启动器在结果面板直接给出这一步的提示。

### 5.5 输出流程（原子、可回滚）

1. 生成到 `<用户目录>/Locale/.pxc_gen_tmp/<lang>/`
2. 自检：文件清单齐全 / JSON 全部可解析 / 节点数 = 骨架数 / 无空串 / 每个字段类型与骨架一致
3. 备份已存在的目标目录（保留最近 1 份）
4. 原子替换到 `Locale/<lang>/`
5. 结果摘要：`节点 942/942、词条 1916/1916、未译 168（回退英文）、新增未译节点 12`

> **未译清单是维护闭环**：运行期发现"对照表里没有的节点/词条"可导出成缺口文件，供构建期补译 —— 这正是"后续版本更新只维护对照表"的落地方式。

### 5.6 兜底规则（找不到英文骨架时）

内置版本 → 最小文件集（实测归纳），并**显著警告覆盖率会下降**：

| 版本区间        | 最小文件集                                            |
| ----------- | ------------------------------------------------ |
| ≤1.19       | `words.json`、`nodes.json`、`config.json`、`fonts/` |
| 1.20.5–1.21 | + `junctions.json`、`notes/`                      |
| ≥1.22       | + `UI.json`（补充键）                                 |

### 5.7 自定义译文层（个性化微调，**不改对照表**）

**定位**：对照表是随程序分发的固定内容，用户不动它；但每个人不习惯的叫法不同（"挤出"还是"挤压"、  
"混合"还是"混合模式"）。自定义译文层是给用户的**最后一步微调**：只存他改过的那几处，其余全部走对照表。

**可改的四类文案（对应浮窗四个分页）**

| 分页 | 文件           | 条目      | 右侧可改的字段                               |
| -- | ------------ | ------- | ------------------------------------- |
| 节点 | `nodes.json` | 942 个节点 | 节点名 / 节点提示 / 输入端口 / 输出端口 / 输入提示 / 下拉项 |
| 词条 | `words.json` | 2019 条  | 该词条的译文（一行）                            |
| 界面 | `UI.json`    | 411 键   | 该键的译文（一行）                             |
| 注释 | `notes/*.md` | 3 篇     | **整篇 markdown**（多行输入框，留空 = 用原版）       |

`junctions.json` 不开放覆盖：它的值只是"指向哪篇 note 的英文文件名"，改它等于改文件引用，  
不是文案（真要改文档内容，去「注释」页）。

**搜索规则（`launcher/search_fold.h`，纯函数，headless 可回归）**

| 维度 | 规则 | 为什么 |
| --- | --- | --- |
| 大小写 | ASCII 折叠为小写 | `2D Extrude` / `2d extrude` 都能搜到 |
| 全半角 | 全角 ASCII（U+FF01–U+FF5E）与全角空格压成半角 | 中文输入法下常打出 `２Ｄ`、`挤出　`，不归一化就永远搜不到 |
| 可搜字段 | ID / 英文原文 / **现用译文** / **对照表原名** | 改过名字后，用户往往记得原来的叫法；只搜现用名会"自己的改动让自己搜不到" |
| 多词 | 整串当子串命中，或按空格切词后**每个词**都出现（顺序无关） | 记不清完整名字时的模糊搜 |
| 首尾空白 | 忽略 | 复制粘贴常带空格 |

四个字段都预存归一化副本（`idL/enL/zhL/zhOrigL`），过滤时**零分配**；942/2018 条也不抖。

**右侧必须显示对照表原文**：改过的字段行显示 `分类名  英文锚  原文：挤出` —— 用户需要知道"我把它改成了什么、  
原来是什么"，否则只剩一个陌生名字，无法判断该不该改回去。原文只在**改过**时出现（没改时输入框本身即原文，  
再显示一遍是噪音）。

**存储**：`launcher.json` → `locale.overrides`：`key -> 文案`。  
键与对照表**完全同构**（`nodes.<id>.name` / `.in.<英文端口名>.name` / `.dd.<英文枚举值>` /  
`words.<k>` / `ui.<k>` / `notes.<英文文件名>`），所以不需要第二套结构。

**优先级（唯一的实现接点）**：`locale_generator::field()` 里 **自定义译文层 → 对照表 → 英文回退**。  
注意 UI.json 的"补充键"分支（骨架没 UI.json 时从对照表补键）也必须走 `field()` ——  
曾漏掉这一处，导致界面类的自定义译文静默失效。

**写入规则**

| 输入框内容  | 结果                      |
| ------ | ----------------------- |
| 空      | 删除该键的自定义译文 → 回到对照表默认译文 |
| 与默认值相同 | 不存（避免"打开一次就把整个节点写进自定义译文层"） |
| 其它     | 存为自定义译文                 |

**必须是英文锚、不能存下标**：理由同 §4.3 —— 换 PXC 版本、对照表更新后仍能对上；存下标则一旦  
`display_data` 长度变化就错译。

**与显示表达式的关系**：自定义译文就是 `%zh` 那一份，仍参与 §5.4 的渲染。所以选了「中文在前」时，  
自定义的节点名也会变成 `自定义_Outline` —— 预期行为（显示模式与个性化互不干扰）。

**导出 / 导入（偏好可携带，入口在汉化页而非浮窗）**

`launcher/override_io`（独立模块，可 headless 测）。**入口位置**：汉化页「生成并应用」下方的
「导出偏好…／导入偏好…」。理由：这份文件同时包含**语言目录名**和**显示表达式**，属于整份偏好，
不是"某一条自定义译文"；放在浮窗底部会让人以为它只导自定义条目。浮窗底部因此只留「清除本条目」「完成」。

- 导出 → 一个只含**差异**的 JSON：`format` / `format_version` / `db_version` /  
  `lang_dir` / `preset` / `slots`（6 个显示表达式）/ `overrides`。  
  不含对照表内容、不含字体绝对路径，所以文件很小（几十条 = 几 KB），可以发给别人或带到另一台机器。
- 导入 → 校验 `format` 后合并：同键以导入值覆盖，本机独有的保留；`preset` / `slots` 一并套用  
  （显示习惯也是偏好）；字体路径不导入（跨设备绝对路径无意义，落地由启动器的字体兜底负责）。
- 导入后界面提示「新增 N / 更新 M / 相同 K」，不静默吞掉。

**性能约定（曾经卡到不可用，改法必须保留）**

| 症状        | 根因                                                            | 现在的做法                                              |
| --------- | ------------------------------------------------------------- | -------------------------------------------------- |
| 打开/切换条目卡顿 | 左侧列表一次构建全部条目并每帧全量重算过滤                                         | 分页数据**懒构建一次**；搜索用预计算的**归一化副本**（`idL/enL/zhL/zhOrigL`），过滤零分配 |
| 输入时掉帧     | 右侧字段区用 `scrollView` 排全部字段，每个字段一个 input，**无虚拟化**               | 右侧改 `virtualList`，行高按分页定（58 / 注释 300），只渲染可见行       |
| 每次保存都顿一下  | `ovSaveAll()` 里重建整页 + 重算过滤（942 × 2 次 map 查找 + 3 个 vector 重分配） | 保存只更新**被编辑那一条**的 `zh/marked`，不动 view、不重建整页         |
| 列表行渲染慢    | 每行现拼 `kNodeName()` 再查 map                                     | 「是否已有自定义译文」在构建时算成 `bool`，行渲染 O(1)                     |

**UI**：汉化页「自定义译文…」按钮 → 浮窗（`components::dialog`，920×620）：  
搜索框**上方**是四个分页（节点/词条/界面/注释），下方左栏是搜索 + 条目列表（已自定义的条目标 ●），  
右栏是选中条目的字段（分类名 + 英文锚 + 改过时附「原文：…」+ 编辑框，改过的行标「已自定义」），  
底部只有「清除本条目」「完成（保存）」+ 状态（导入/导出在汉化页，理由见上）。  
切换分页/条目、关闭浮窗、点遮罩都会先把编辑写回配置。
